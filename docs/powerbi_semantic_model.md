# Power BI Semantic Model (Phase 9)

**Status:** Phase 9 deliverable (in review) · **Sources:** Phase 7 `bc2023b`, Phase 8 `7438ee7` · **Snowflake schema:** `AUTONOMOUS_MOBILITY.ANALYTICS`, tables `PBI_*`

The semantic model **reports** the approved analysis. Its publication tables copy the Phase 7 scoring relations and the committed Phase 8 outputs. No score, rank, weight or frequency is recalculated. The single derived value is `regulatory_score` in the regulatory-uncertainty fact (§2), an algebraic back-out.

The build steps are in [powerbi/BUILD_GUIDE.md](../powerbi/BUILD_GUIDE.md), the measures in [powerbi/measures.md](../powerbi/measures.md), and the column documentation in [powerbi/data_dictionary.csv](../powerbi/data_dictionary.csv).

## 1. Architecture

```
Public sources → Snowflake RAW → dbt STAGING → INTERMEDIATE → CORE → ANALYTICS feature marts
  → Phase 7 readiness model (ANALYTICS FCT_*) ─┐
  → Phase 8 robustness (outputs/phase8 → generated dbt seeds, INTERMEDIATE.P8_*) ─┤
                                                └→ ANALYTICS.PBI_* publication layer → Power BI (Import)
```

- **Phase 7 results** are already in Snowflake, and the publication tables read them directly.
- **Phase 8 results** are committed CSVs. They enter through deterministic seeds generated by `scripts/build_powerbi_seeds.py`, never hand-edited, and verified by `--check` and by the publication QA.
- **Power BI** connects with **AM_ANALYST**. That role can read CORE and ANALYTICS only; INTERMEDIATE, the seeds and RAW are not visible to it (verified).

**Key behaviours of the facts:**
- **Robotaxi C5.** It is structurally absent: no Component Scores row, no Feature row, and a NULL `c5_weight` on every robotaxi scenario.
- **Incomplete regulatory evidence.** Baseline score and rank stay **blank**: 6 robotaxi, 4 sidewalk and 10 drone markets. Their regulatory bounds are in *Regulatory Uncertainty*.
- **Regulatory back-out.** *Regulatory Uncertainty* `regulatory_score` = (scenario score − non-regulatory contributions) / C4 weight. For complete markets it equals the Phase 7 C4; a dbt test checks this to 1e-4.
- **Deployment.** *Deployment Validation* is **external validation only**. No scoring or robustness table contains or reads deployment fields; this is enforced by dbt tests and lineage QA.

**Deliberate choices:**
- *Business Scenario* and *Feature Contribution* are **not** related to Mode directly. Mode filters them through Scenario and Feature. A direct relationship would create an ambiguous second path.
- *Feature Contribution* is not related to Component directly, for the same reason: Component reaches it through Feature.
- There are **no bidirectional relationships** and **no fact-to-fact relationships**. Measures read the market × mode facts side by side.
- The four What-If weight parameters and the C5 parameter are **disconnected tables** ([powerbi/measures.md](../powerbi/measures.md) §5).

## 4. Connectivity: Import (recommended)

| | Import | DirectQuery |
|---|---|---|
| Data size | About 3,000 rows in 13 tables, a few MB at most | Same |
| Change frequency | Static between analytical releases (each release is a commit) | Same |
| Performance | In-memory; instant slicers and RANKX over 35 markets | Every visual queries Snowflake; RANKX What-If measures would issue many queries |
| Cost | One refresh per release | Warehouse credits on every interaction (the 10-credit monitor, A-058) |
| DAX | Full DAX, including What-If parameters | Restricted |

**Decision: IMPORT.** There is no concrete reason for DirectQuery: the data is tiny and changes only when a new analytical release is published. Refresh is manual, after the refresh workflow ([powerbi_refresh_workflow.md](powerbi_refresh_workflow.md)).

## 5. Model hygiene

- **Hidden columns.** Hide every foreign key on facts, plus technical columns. `data_dictionary.csv` marks 39 columns `HIDE`.
- **Formats.** Formats come from the dictionary:
  - scores to 1 decimal place (0.0);
  - ranks as whole numbers (0);
  - frequencies and shares as percentages (0.0%).
- **Sorting.** Sort by the dimension `sort_order` columns: Mode, Component and Scenario.
- **Summarization.** Set "Don't summarize" on every numeric fact column. Users interact through the measures only.
